🐧 Добро пожаловать в мир Linux

Это комплексное руководство покрывает всё: от истории создания Linux до продвинутых техник работы в терминале. Здесь вы найдёте не только сухую теорию, но и практические примеры, советы и рекомендации, которые помогут вам стать уверенным пользователем.

📌 О этом руководстве

Материал структурирован от простого к сложному. Рекомендуется проходить разделы последовательно, особенно если вы новичок. Каждый раздел содержит практические примеры для самостоятельного выполнения.

💭 Почему Linux?

В мире, где операционные системы становятся всё более «закрытыми садами», Linux остаётся последним бастионом цифрового суверенитета. Когда вы работаете в терминале, вы не просите систему выполнить вашу просьбу — вы отдаёте приказ. Это чувство прямого контроля над «железом» — то, что делает Linux уникальным.

🚀 Быстрый старт

  • Установите Linux на виртуальную машину для безопасного обучения
  • Не бойтесь экспериментировать — система создана для этого
  • Используйте man [команда] для получения справки
  • Сохраняйте важные команды в файл для быстрого доступа

Как пользоваться этим руководством

  1. Навигация: Используйте левую панель для перехода между разделами
  2. Поиск: Введите ключевое слово в поле поиска для быстрого нахождения информации
  3. Практика: Все примеры в терминале можно повторить на своей системе
  4. Прогресс: Отмечайте пройденные разделы в панели прогресса

📜 История Linux

Происхождение и создание

Linux — это операционная система с открытым исходным кодом, ядро которой было создано Линусом Торвальдсом в 1991 году. Будучи студентом Хельсинкского университета, Торвальдс начал писать ядро как хобби-проект, желая создать систему, похожую на MINIX, но свободную от её ограничений.

📅 Ключевая дата

25 августа 1991 года — Линус Торвальдс опубликовал первое сообщение в группе новостей comp.os.minix о своём проекте.

GNU/Linux: Почему два имени?

Важно понимать различие между Linux и GNU/Linux:

  • Linux — это только ядро операционной системы (движок автомобиля)
  • GNU — это набор утилит и программ, которые делают систему usable (кузов, колёса, руль)
  • GNU/Linux — полная операционная система, сочетающая ядро Linux с утилитами GNU
⚠️ Частая ошибка

Многие называют всю систему просто "Linux", но технически правильнее говорить "GNU/Linux", так как без утилит GNU (компилятор GCC, оболочка Bash, базовые команды) ядро было бы бесполезно для пользователя.

Эволюция использования

Период Основное применение Ключевые события
1991-1995 Хобби, образование Первые дистрибутивы (Slackware, Debian)
1996-2000 Серверы Apache + Linux доминируют в вебе
2001-2010 Корпоративный сектор Red Hat Enterprise, Ubuntu Desktop
2011-настоящее Везде Android, облака, суперкомпьютеры, IoT

🏆 Современные достижения

100% суперкомпьютеров из TOP500 работают на Linux. 90% облачных серверов используют Linux. Android (на базе ядра Linux) — самая популярная ОС в мире с миллиардами устройств.

🧠 Философия Unix

Философия Unix — это набор культурных норм и подходов к разработке программного обеспечения, которые возникли в Bell Labs в 1970-х годах. Эти принципы лежат в основе Linux и определяют, как создаются инструменты для этой системы.

Основные принципы

  1. Делай одну вещь, но делай её хорошо — каждая программа должна решать одну задачу
  2. Программы должны работать вместе — возможность комбинирования через конвейеры
  3. Текстовые данные — универсальный интерфейс — текст легко обрабатывать и передавать
  4. Избегай захвата пользователя — программа не должна удерживать пользователя в своём интерфейсе
  5. Доверяй программисту — давай возможность делать опасные вещи, если он этого хочет
💡 Практическое применение

Вместо создания одного монолитного приложения, которое делает всё (редактирование, поиск, сортировка), Unix-подход предлагает создать отдельные инструменты для каждой задачи и соединить их вместе.

Пример философии в действии

Задача: Найти 5 самых частых слов в файле

# Вместо одной сложной программы используем конвейер:
cat document.txt | tr ' ' '\n' | sort | uniq -c | sort -rn | head -5
  • cat — читает файл (одна задача)
  • tr — заменяет пробелы на переносы строк (одна задача)
  • sort — сортирует слова (одна задача)
  • uniq -c — подсчитывает повторения (одна задача)
  • sort -rn — сортирует по количеству (одна задача)
  • head -5 — показывает первые 5 строк (одна задача)

📁 Файловые системы Linux

Файловая система (ФС) — это способ организации, хранения и именования данных на носителях. В Linux ФС — это не просто формат диска, а фундаментальная часть архитектуры системы.

Иерархия файловой системы (FHS)

В отличие от Windows с дисками C:, D:, Linux использует единое дерево каталогов:

Каталог Назначение Аналог в Windows
/ Корень файловой системы Мой компьютер
/home Домашние директории пользователей C:\Users
/etc Конфигурационные файлы системы Реестр + Program Files
/var Переменные данные (логи, кэш) C:\Windows\Temp
/usr Пользовательские программы C:\Program Files
/bin Основные исполняемые файлы C:\Windows\System32

Исторические ФС

  • ext (1992) — Первая ФС для Linux. Сейчас устарела.
  • ext2 (1993) — Классическая ФС без журналирования. Быстрая, но при сбое питания данные могли быть потеряны.
  • ReiserFS (2001) — Популярная в начале 2000-х, отличалась высокой скоростью работы с мелкими файлами.

Современные ФС

ФС Описание Рекомендация
ext4 Стандарт де-факто. Надёжная, с журналированием, поддерживает до 1 ЭБ данных. ✅ Для большинства пользователей
XFS Высокопроизводительная, отлично масштабируется. Любит большие файлы. ✅ Для серверов и медиа
Btrfs Снапшоты, сжатие на лету, проверка контрольных сумм. Copy-on-Write. ⚠️ Для продвинутых пользователей
ZFS Мощнейшая ФС. Лучшая защита данных, но сложна в лицензировании. ⚠️ Для корпоративных серверов
🔍 Что такое журналирование?

Представьте, что вы пишете книгу. Журналирование — это когда вы сначала записываете план главы в черновик (журнал), и только потом пишете саму главу. Если свет погаснет, вы не потеряете структуру книги. Без журналирования сбой питания мог превратить файл в кашу из байтов.

💡 Copy-on-Write (CoW)

Технология в Btrfs и ZFS. При изменении файла система не перезаписывает старые данные, а пишет новые в другое место, а затем меняет указатель. Это позволяет делать мгновенные снимки системы без потери производительности.

💻 Терминал и базовые команды

Терминал — это текстовый интерфейс для взаимодействия с операционной системой. Несмотря на наличие графических интерфейсов, терминал остаётся самым мощным инструментом администратора.

Навигация

Команда Описание Пример
pwd Показать текущий путь pwd → /home/user
ls Список файлов ls -la (все файлы, подробно)
cd Сменить директорию cd /etc
mkdir Создать папку mkdir new_folder

Работа с файлами

Команда Описание Пример
cp Копировать cp file.txt backup.txt
mv Переместить/переименовать mv old.txt new.txt
rm Удалить rm file.txt ⚠️
cat Показать содержимое cat file.txt
less Постраничный просмотр less large_file.log
⚠️ Осторожно с rm!

Команда rm удаляет файлы без возможности восстановления. Команда rm -rf / может уничтожить всю систему. Всегда проверяйте путь перед удалением!

Главная / Терминал / Конвейеры

🔗 Конвейеры и перенаправление

Конвейеры (pipes) — это одна из самых мощных возможностей Unix-систем. Они позволяют соединять вывод одной программы с вводом другой, создавая сложные цепочки обработки данных.

Символы перенаправления

Символ Назначение Пример
| Конвейер (pipe) ls | grep txt
> Перенаправление вывода echo "text" > file.txt
>> Добавить в конец файла echo "more" >> file.txt
< Перенаправление ввода sort < input.txt
2> Перенаправление ошибок command 2> errors.log

Практические примеры конвейеров

1. Поиск файлов по размеру

find /home -type f -size +100M | sort -rh | head -10

Найти файлы больше 100МБ, отсортировать по размеру, показать 10 крупнейших.

2. Анализ логов

cat /var/log/syslog | grep "error" | wc -l

Посчитать количество строк с "error" в системном логе.

3. Мониторинг процессов

ps aux | grep python | grep -v grep

Найти все процессы Python, исключив саму команду grep.

4. Сложный анализ текста

cat document.txt | tr '[:upper:]' '[:lower:]' | tr -cs '[:alpha:]' '\n' | sort | uniq -c | sort -rn | head -20

Показать 20 самых частых слов в документе (игнорируя регистр).

💡 Философия в действии

Обратите внимание: каждая команда в конвейере делает одну вещь. tr только заменяет символы, sort только сортирует, uniq только убирает дубликаты. Но вместе они решают сложную задачу!

Полезные команды для конвейеров

  • grep — поиск текста по шаблону
  • awk — обработка столбцов текста
  • sed — потоковый редактор текста
  • cut — вырезать части строк
  • sort — сортировка строк
  • uniq — убрать дубликаты
  • wc — подсчёт строк, слов, символов
  • head / tail — первые/последние строки
Главная / Терминал / Архивы

📦 Работа с архивами

В Linux часто встречаются архивы с расширением .tar.gz или .tar.bz2. Это "тарболы" — файлы, сначала упакованные утилитой tar, а затем сжатые.

Понимание расширений

Расширение Описание Команда
.tar Только упаковка (без сжатия) tar -cvf
.tar.gz tar + gzip сжатие tar -czvf
.tar.bz2 tar + bzip2 сжатие (лучше) tar -cjvf
.zip ZIP архив zip / unzip
.rar RAR архив rar / unrar

Основные команды

Создание архива

# Создать tar.gz архив из папки
tar -czvf archive.tar.gz /path/to/folder

# Создать tar.bz2 архив (лучшее сжатие)
tar -cjvf archive.tar.bz2 /path/to/folder

Извлечение архива

# Распаковать tar.gz
tar -xzvf archive.tar.gz

# Распаковать tar.bz2
tar -xjvf archive.tar.bz2

# Распаковать zip
unzip archive.zip

# Распаковать rar
unrar x archive.rar

Просмотр содержимого

# Показать файлы в архиве без распаковки
tar -tzvf archive.tar.gz
📝 Флаги tar
  • c — create (создать)
  • x — extract (извлечь)
  • t — table of contents (содержимое)
  • z — gzip
  • j — bzip2
  • v — verbose (показывать процесс)
  • f — file (указать имя файла)

🖥️ Среды рабочего стола (Desktop Environments)

Что такое Desktop Environment (DE)?

Графическое окружение — это совокупность программ, обеспечивающих графический интерфейс пользователя. Оно включает:

  • Панель задач и меню приложений
  • Файловый менеджер
  • Дисплей-менеджер (экран входа)
  • Набор стандартных приложений
  • Оконный менеджер

Популярные окружения (2026)

Среда Краткое описание Сценарии использования
GNOME Современная, минималистичная среда, фокусирующаяся на чистоте. Версия 49 полностью отказалась от X11 в пользу Wayland. Рабочие станции, где важен простор. Стандарт для Fedora, Ubuntu, RHEL.
KDE Plasma Невероятно гибкая и настраиваемая среда с классическим видом. Версия 6.5 сочетает стабильность и кастомизацию. Для пользователей, которые хотят настроить каждую деталь интерфейса под себя.
Cinnamon Традиционная среда с классической панелью и меню "Пуск". Обеспечивает знакомый опыт. Лучший выбор для мигрантов с Windows, желающих привычный интерфейс.
COSMIC Новая среда от System76 на Rust. Высокая производительность и безопасность. Разработчики и энтузиасты, желающие испытать передовые технологии (Pop!_OS).
XFCE Легковесная, но полнофункциональная среда. Потребляет мало ресурсов. Старые компьютеры или пользователи, ценящие скорость выше эффектов.
MATE Продолжение GNOME 2. Классический, традиционный интерфейс. Для тех, кто скучает по старому GNOME 2 или ищет стабильность.

Pantheon Элегантная и простая среда для elementary OS. Строгий дизайн. Пользователи, ценящие минимализм и эстетику в стиле macOS.

Deepin (DDE) Одна из самых визуально впечатляющих сред с элегантными приложениями. Для пользователей, для которых внешний вид имеет первостепенное значение.
LXDE Классическая легковесная среда. Развитие сместилось в сторону LXQt. Максимальная экономия ресурсов на очень старом оборудовании.

Терминальные эмуляторы

  • Kitty — GPU-ускоренный, быстрый, поддерживает лигатуры и изображения
  • GNOME Terminal — Стандарт для GNOME, простой и функциональный
  • Konsole — Мощный терминал для KDE
  • Alacritty — Минималистичный, сверхбыстрый (Rust)
  • WezTerm — Современный, с Lua-скриптингом
💡 Почему стиль LXDE?

Этот сайт стилизован под LXDE не просто так. LXDE символизирует философию эффективности — в эпоху, когда простой текстовый редактор потребляет 500 МБ RAM, лёгкий интерфейс напоминает: ПО должно служить пользователю, а не пожирать ресурсы.

🪟 Оконные менеджеры (Window Managers)

🤔 Что такое Оконный Менеджер (WM)?

Оконный менеджер — это системное программное обеспечение, которое отвечает за размещение и внешний вид окон приложений в графической пользовательской среде.

Главное отличие от DE: Если Desktop Environment (как KDE или GNOME) — это «полностью оборудованная кухня» (есть плита, холодильник, посуда, декор), то Оконный Менеджер — это просто «плита и холодильник». Он управляет окнами, но не предоставляет панели задач, меню «Пуск», настроек системы или файлового менеджера «из коробки». Всё это нужно доустанавливать отдельно.

Зачем использовать WM?

  • Производительность: WM потребляют минимум оперативной памяти (часто <100 МБ) и ресурсов CPU.
  • Контроль: Полная кастомизация поведения окон через конфиги.
  • Эффективность: Плиточные менеджеры (Tiling WM) позволяют работать исключительно с клавиатуры, не трогая мышь.
  • Эстетика: Возможность создать уникальный, минималистичный интерфейс (как в фильмах про хакеров).

Популярные оконные менеджеры

WM Тип Краткое описание Сценарии
i3 Плиточный (Tiling) Самый популярный WM. Управляется с клавиатуры, конфиг через текстовый файл. Работает на X11. Программисты, сисадмины, ценители эффективности.
Sway Плиточный (Tiling) Полный клон i3, но работающий нативно на Wayland.Drop-in замена для i3. Те же, что и i3, но для пользователей Wayland.
Awesome Плиточный (Dynamic) Высококонфигурируемый WM на Lua. Позволяет создавать сложные динамические макеты. Пользователи, готовые писать скрипты на Lua для уникальной настройки.
Openbox Стековый (Floating) Легкий менеджер, окна плавают как в Windows. Конфиг через XML. Часто используется в минималистичных сборках. Старые ПК или создание собственной легковесной среды (с панелью tint2).
Fluxbox Стековый (Floating) Потомок Blackbox. Очень быстрый, настраивается через текстовые файлы. Максимальная скорость на устаревшем оборудовании.
dwm Плиточный (Tiling) От сообщества suckless.org. Минимализм. Настраивается через редактирование исходного кода на C и перекомпиляцию. Энтузиасты, желающие полный контроль над каждой строчкой кода.
Qtile Плиточный (Tiling) Написан и настраивается на Python. Python-разработчики и все, кто хочет легко модифицировать WM.
Hyprland Плиточный (Wayland) Современный композитор с динамическими макетами, плавными анимациями и эффектами. Пользователи, желающие красоты Wayland + эффективности тайлинга.
bspwm Плиточный (Tiling) Управляет только окнами. Всё остальное (панели, хоткеи) делегируется внешним утилитам (polybar, sxhkd). Любители модульного подхода (Unix-way).
JWM Стековый (Floating) Очень лёгкий менеджер на C. Используется в Puppy Linux, Besgnulinux. Системы с крайне ограниченными ресурсами.
🧩 Как это собрать?

Типичная сборка на базе WM выглядит так:
WM (i3/Sway) + Панель (Polybar/Waybar) + Лаунчер (Rofi/Wofi) + Терминал (Kitty/Alacritty) + Обои (Nitrogen/Swaybg).

Главная / Графика / X11 vs Wayland

🔄 X11 vs Wayland

В мире Linux происходит тихая революция — переход от старого протокола X11 к современному Wayland. Это важное изменение, которое влияет на производительность, безопасность и совместимость.

Сравнение протоколов

Характеристика X11 (Xorg) Wayland
Возраст 35+ лет (1987) 10+ лет (2012)
Архитектура Клиент-сервер Композитор = сервер
Безопасность Низкая (кейлоггеры возможны) Высокая (изоляция приложений)
Производительность Средняя Высокая (меньше копирований)
Мультимонитор Проблемы с разным DPI Отличная поддержка
Совместимость Полная Растущая (XWayland)

Как проверить свой протокол?

echo $XDG_SESSION_TYPE

Вернёт x11 или wayland.

📊 Текущее состояние (2026)

Fedora, Ubuntu, Debian по умолчанию используют Wayland. Некоторые приложения (особенно для записи экрана и удалённого доступа) могут работать некорректно. XWayland обеспечивает совместимость со старыми X11 приложениями.

Рекомендации

  • Для новых систем: Используйте Wayland по умолчанию
  • Для игр: Wayland показывает лучшую производительность в большинстве случаев
  • Для записи экрана: Может потребоваться X11 (ситуация улучшается)
  • Для NVIDIA: Wayland теперь хорошо поддерживается (драйверы 555+)

🌳 Семейство Unix

Определения

  • Unix — Операционная система, разработанная в Bell Labs в 1969. Сейчас торговая марка принадлежит The Open Group.
  • Unix-подобные (Unix-like) — Системы, которые ведут себя как Unix, но не обязательно имеют сертификат.
  • POSIX — Стандарт, определяющий совместимость с Unix.

🏷️ Почему Linux не сертифицирован?

Сертификация Unix стоит денег ($500,000+). Linux-сообщество не видит смысла платить за сертификат, когда система и так совместима. Технически Linux — Unix-like, но функционально эквивалентен Unix.

Главная / Экосистема / BSD и macOS

🍎 BSD системы и macOS

Что такое BSD?

Berkeley Software Distribution (BSD) — это операционная система, произошедшая непосредственно от оригинального Unix из Bell Labs. В отличие от Linux (который является только ядром), BSD-системы распространяются как целостные ОС.

💡 Ключевое отличие

Linux = ядро + отдельные пакеты от разных разработчиков. BSD = единая команда разрабатывает ядро, драйверы и утилиты вместе в одном репозитории.

Основные ветви BSD

Система Фокус Особенности
FreeBSD Производительность Стабильность, сеть, ZFS. Netflix использует для CDN.
OpenBSD Безопасность Аудит кода, криптография. "Только 2 дыры по умолчанию".
NetBSD Портативность "Конечно, это работает на NetBSD". Работает на тостерах.
DragonFly BSD Инновации HAMMER ФС, масштабируемость многоядерных систем.

macOS и BSD

macOS — это уникальная система. Её ядро называется Darwin, которое основано на FreeBSD и Mach (микроядро).

Почему macOS считается Unix?

  • Прошла сертификацию The Open Group как UNIX 03
  • Терминал практически идентичен Linux/BSD (zsh/bash)
  • Структура ФС (/bin, /etc, /usr, /var) соответствует стандарту Unix
  • Большинство Linux-команд работают идентично

🎯 macOS для разработчиков

Mac популярен среди веб-разработчиков именно потому, что сочетает Unix-терминал (как Linux) с коммерческим софтом (Adobe, Office). Вы получаете лучшее из обоих миров: мощь командной строки и удобство проприетарных приложений.

🔐 Права доступа

Система прав доступа — фундамент безопасности Linux. Понимание chmod и chown критически важно для любого пользователя.

Структура прав

-rwxr-xr--  1 user  group  4096 Oct 25 10:00 file.txt
│││││││││
││││││││└─── Другие (others): r-- (читать)
││││││└───── Группа (group): r-x (читать+исполнять)
││││└──────── Владелец (user): rwx (читать+писать+исполнять)
│││└────────── Специальные биты (setuid, setgid, sticky)
││└─────────── Тип файла (- файл, d директория, l ссылка)
└────────────── Всего 10 символов

Числовое представление

Право Буква Число
Чтение r 4
Запись w 2
Исполнение x 1

Примеры использования chmod

# Сделать файл исполняемым
chmod +x script.sh

# Полные права владельцу, чтение группе и другим
chmod 744 file.txt

# Стандартные права для скрипта
chmod 755 script.sh

# Только чтение для всех
chmod 444 file.txt

# Рекурсивно для папки
chmod -R 755 /path/to/folder

chown — смена владельца

# Сменить владельца
chown user file.txt

# Сменить владельца и группу
chown user:group file.txt

# Рекурсивно
chown -R user:group /path/to/folder
⚠️ Критические права

Никогда не делайте chmod 777 на системные файлы или домашние директории. Это открывает доступ всем пользователям и является серьёзной уязвимостью безопасности.

sudo — временные привилегии

# Выполнить команду как root
sudo apt update

# Открыть оболочку root
sudo -i

# Выполнить команду от другого пользователя
sudo -u username command

🗺️ Путь изучения Linux

Этот roadmap поможет вам структурировать обучение и прогрессировать от новичка до продвинутого пользователя.

Уровень 1: Выживание (The Survivor)

📋 Цели
  • Установить Linux на виртуальную машину (VirtualBox/VMware)
  • Научиться обновлять систему
  • Не бояться терминала
  • Понимать базовую структуру ФС

Команды для изучения

ls cd pwd cp mv rm mkdir sudo apt/dnf/pacman

Уровень 2: Навигатор (The Navigator)

📋 Цели
  • Перемещаться по ФС без мыши
  • Понимать права доступа
  • Работать с текстовыми редакторами (nano, vim)
  • Использовать конвейеры

Команды для изучения

grep find chmod chown vim/nano man history pipe |

Уровень 3: Архитектор (The Architect)

📋 Цели
  • Настроить веб-сервер (Nginx/Apache)
  • Автоматизировать задачи (cron, bash скрипты)
  • Понимать процессы и сервисы
  • Работать с сетью

Команды для изучения

systemctl ps top/htop netstat/ss ssh crontab bash scripting

Уровень 4: Мастер (The Master)

📋 Цели
  • Написать собственные скрипты и утилиты
  • Оптимизировать производительность системы
  • Понимать ядро и модули
  • Администрировать серверы в продакшене

Темы для изучения

Kernel tuning Security hardening Containerization CI/CD Monitoring

🎯 Главный совет

Не бойтесь сломать систему. Установите Linux на виртуальную машину, попробуйте удалить критический файл, посмотрите на ошибку, восстановите из снапшота. Именно на ошибках мы учимся лучше всего. Каждая поломка — это урок, который сделает вас сильнее.
